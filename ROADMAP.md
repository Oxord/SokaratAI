# Sokrat — Roadmap развития продукта

> Цель документа: зафиксировать, куда двигаем продукт, какие фичи делают его
> сильным и в каком порядке их реализуем. Опирается на то, что уже работает в коде.

---

## 1. Проблема и позиционирование

**Проблема.** Кандидат готовится к собеседованию по абстрактным спискам вопросов
("200 вопросов по Python"), а на реальном интервью его спрашивают про стек, продукты
и задачи *конкретной* компании. Готовиться тревожно и непонятно, к чему именно.
Живой тренер или mock-интервью с ментором — дорого и недоступно массово.

**Что делает Sokrat.** AI-тренажёр, который проводит mock-интервью *под конкретную
вакансию и компанию кандидата* и по итогам даёт измеримый разбор и план подготовки.

### Уникальное торговое предложение (USP)

> **«Репетиция именно того собеседования, на которое ты идёшь.»**
> Вакансия + компания + твоё резюме → персональное интервью → разбор пробелов → план.

Отличие от аналогов (общие банки вопросов, универсальные чат-боты):
персонализация по трём источникам одновременно — **вакансия, компания, кандидат**.

## 3. Фичи, которые усиливают проект

Приоритет: **P0** — делаем в ближайшем цикле и показываем жюри; **P1** — следующий
этап; **P2** — задел на грант. Сложность: S (1–2 дня), M (3–5 дней), L (больше недели).

### 3.1 Персонализация (ядро USP)

| # | Фича | Суть | Приоритет | Сложность |
|---|---|---|---|---|
| A1 | **Профиль компании** | По названию компании из вакансии собираем: чем занимается, продукты, публичный технологический стек, культура. Источники: описание работодателя в API hh.ru, сайт компании, технические блоги (Habr и т.п.). Вопросы начинают ссылаться на реальные продукты ("Как бы вы масштабировали сервис онлайн-платежей в нашем приложении?") | P0 | M |
| A2 | **Парсинг резюме** | Загрузка PDF/DOCX/текста → структурированный профиль: опыт, стек, проекты, уровень. Бот задаёт вопросы по *заявленному* опыту ("В резюме указан Kafka — расскажите, как гарантировали порядок сообщений") | P0 | M |
| A3 | **Gap-анализ: резюме ↔ вакансия** | Сравниваем навыки кандидата и требования вакансии. Результат до интервью: что совпадает, чего не хватает, на что сделать упор. Интервью строится вокруг пробелов | P0 | M |
| A4 | **Персона интервьюера** | Стиль под компанию: строгий банковский, продуктовый стартап, большая ИТ-компания. Влияет на тон, глубину, тип вопросов | P1 | S |
| A5 | **Мульти-вакансия** | Подготовка сразу к нескольким офферам, сравнение готовности к каждой | P2 | M |

## 4. Этапы

### Этап 1 — "Сильная демонстрация" (ближайшее время)

Цель: показать жюри сквозной сценарий **резюме + вакансия + компания → персональное
интервью → план подготовки**.

1. A1 Профиль компании
2. A2 Парсинг резюме
3. A3 Gap-анализ резюме ↔ вакансия
4. C3 Индекс готовности к вакансии
5. B1 STAR-режим для поведенческих вопросов
6. Починить расхождения: единый банк вопросов, актуализировать `PRESENTATION_BRIEF.md`

**Демо-сценарий для защиты:** пользователь вставляет ссылку на вакансию Сбера →
Sokrat показывает профиль компании и стек → загружает резюме → видит gap-анализ →
проходит интервью, где вопросы про реальные продукты банка и пункты резюме →
получает радар, индекс готовности и план на неделю.

### Этап 2 — "Продукт, к которому возвращаются"

C1 История и динамика, C2 План подготовки, B5 Повторение слабых тем, B4 Голос (TTS),
B3 Стресс-режим, A4 Персоны интервьюера, D3 Источники вакансий, D5 Качество вопросов.

### Этап 3 — "Масштаб и деньги" (под грант)

B2 Практические блоки (код, system design), D1/D2 B2B-кабинеты, A5 Мульти-вакансия,
D4 Мультиязычность, C4 Шеринг, публичное API.

## 5. Техническая реализация ключевых фич

### A1 Профиль компании

- Новый модуль `sokrat/company_profile.py` рядом с `vacancy_parser.py`.
- Источники по убыванию надёжности: `api.hh.ru/employers/<id>` (id берётся из вакансии),
  страница компании/о нас, поиск публикаций в техблогах.
- LLM-экстракция в структуру `CompanyProfile`: `industry`, `products[]`, `tech_stack[]`,
  `engineering_culture`, `recent_initiatives[]`, `sources[]` — с обязательным списком
  источников, чтобы пользователь видел, откуда факты.
- Кэш по `company_id` с TTL, чтобы не ходить в сеть на каждую сессию.
- В `as_prompt_context()` вакансии добавляется блок компании; промпт
  `question_generator.txt` получает указание привязывать вопросы к продуктам.

### A2 Парсинг резюме

- `sokrat/resume_parser.py`: извлечение текста из PDF/DOCX (`pypdf`, `python-docx`) и
  LLM-структуризация в `ResumeProfile` (опыт, стек, проекты, достижения, уровень).
- Загрузка файла через `cl.AskFileMessage` в Chainlit.
- Персональные данные: резюме обрабатывается в рамках сессии, не логируется целиком;
  при сохранении сессии хранится только структурированный профиль без контактов.

### A3 Gap-анализ

- `sokrat/gap_analysis.py`: сопоставление `ResumeProfile.skills` и
  `VacancyContext.skills` → `matched[]`, `missing[]`, `weak_evidence[]`.
- Результат подаётся в генератор вопросов (упор на `missing` и `weak_evidence`) и в
  итоговый отчёт ("что закрыли, что осталось").

### C3 Индекс готовности

- Взвешенная сумма: покрытие требований вакансии (`skills_coverage`), баллы по
  измерениям радара, результат на вопросах по компании.
- Прозрачная формула в отчёте — без "магического" числа.

## 6. Метрики успеха

| Метрика | Зачем |
|---|---|
| Доля завершённых интервью | Удерживает ли сценарий |
| Доля сессий по реальной вакансии vs по абстрактной роли | Работает ли USP |
| Прирост среднего балла между 1-й и 3-й сессией пользователя | Доказывает пользу тренировки |
| Доля пользователей с ≥2 сессиями | Возвращаемость |
| Субъективная оценка "вопросы были как на реальном собеседовании" (1–5) | Прямая проверка ценности персонализации |

## 7. Риски и как их закрываем

| Риск | Что делаем |
|---|---|
| Данные о компании неточны или устарели | Показываем источники, разрешаем пользователю поправить профиль, кэш с TTL |
| Сайты блокируют парсинг | Приоритет официальных API (hh.ru), вставка текста как запасной путь |
| Галлюцинации LLM в фактах о компании | Факты только из найденных источников; без источника — не утверждаем |
| Персональные данные в резюме | Минимизация хранения, анонимизация, явное согласие, ориентир на 152-ФЗ |
| Стоимость LLM-вызовов | Кэш профилей, облегчённая модель для экстракции, лимиты на сессию |
| Качество оценки ответов субъективно | Эталонные ответы, калибровка на наборе размеченных ответов, показ критериев |

## 8. На что пойдёт грант

- Разработка этапов 2–3: история и аналитика, голос, практические блоки.
- Оплата LLM/STT/TTS-вызовов для пилота с реальными пользователями.
- Пилоты с вузами и карьерными центрами, сбор метрик из раздела 6.
- Экспертная курация банка вопросов и калибровка оценки.
- Инфраструктура: хостинг, хранение, безопасность персональных данных.
